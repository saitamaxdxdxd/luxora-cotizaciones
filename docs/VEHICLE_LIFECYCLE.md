# LUXORA Vehicle Lifecycle Management

## Overview

The Vehicle module has been refactored from a simple flat entity into a **modular, scalable lifecycle management system**. Rather than overloading the `Vehicle` entity, related data (insurance, maintenance, taxes, etc.) is stored in separate, normalized entities—following the same localStorage persistence pattern used throughout LUXORA.

## Architecture

### Core Principle: Separation of Concerns

```
Vehicle (core fleet metadata)
├── VehicleInsurance (policy records)
├── VehicleVerification (verification/verification records)
├── VehicleMaintenance (service history)
├── VehicleTax (tenencia/refrendo)
└── Alerts (automated warnings)
```

**Why modular?**
- Single-entity operations (create, update, delete) without cascading complexity
- Easy to extend with new entity types
- Cleaner data migration to backend APIs (each entity becomes its own collection)
- No bloated vehicle objects
- Alerts can be queried independently for dashboard aggregation

### Alert

```typescript
interface Alert {
  id: string;
  entityType: AlertEntityType;  // "vehicle", "operator", "case", "user"
  entityId: string;             // vehicle ID, operator ID, etc.
  alertType: AlertType;         // insurance_expiring, verification_expired, etc.
```

**Purpose:** Centralized alert system for all operational issues. Automatically generated by `checkVehicleAlerts()` to avoid duplicate warnings.

## Alert Engine

### checkVehicleAlerts()

Called on dashboard load or vehicle detail view. Scans all vehicles and automatically generates alerts for:

1. **Insurance Expiring** (≤30 days)
   - Creates `Alert.alertType = "insurance_expiring"`
   - Severity escalates from `medium` (30 days) to `high` (expired)

2. **Verification Expired**
   - Creates `Alert.alertType = "verification_expired"`
   - Severity escalates similarly

3. **Maintenance Due**
   - Creates `Alert.alertType = "maintenance_due"` when vehicle reaches 90% of next scheduled mileage

4. **Unpaid Taxes**
   - Creates `Alert.alertType = "tax_due"` for unpaid taxes ≤30 days from due date
   - Severity escalates to `high` if overdue

### Duplicate Prevention

The engine checks `alertAlreadyExists(entityType, entityId, alertType)` before creating each alert. This prevents duplicate warnings for the same issue.

### Example Flow

```typescript
// On Vehiculos page load or manual refresh
checkVehicleAlerts();

// Scans all vehicles + related records
// Generates missing alerts
// User sees alerts in "Alertas" tab

// User clicks "Marcar" to resolve
resolveAlert(alertId);  // Sets alert.resolved = true
```

```typescript
  overall: "healthy" | "warning" | "critical";
  insuranceStatus: "ok" | "warning" | "expired";
  verificationStatus: "ok" | "warning" | "expired";
  maintenanceStatus: "ok" | "due";
  taxStatus: "ok" | "warning" | "overdue";
  alertCount: number;
  criticalAlertCount: number;
}
```

Used in:
- Vehicle list cards (shows health badge)
- Vehicle detail view (displays in header)
- Dashboard alerts widget

### isVehicleOperational(vehicle)

Returns `false` if:
- Insurance is expired
- Verification is expired
- Taxes are overdue

Used to prevent renting unsafe vehicles.

## Data Migration to Production Backend

When moving to NestJS + MongoDB:

### Step 1: API Endpoints

```typescript
// Create NestJS controllers for each entity

// POST /api/vehicles/:vehicleId/insurances
// GET /api/vehicles/:vehicleId/insurances
// PATCH /api/insurances/:id
// DELETE /api/insurances/:id

// Similar pattern for verifications, maintenance, taxes, alerts
```

### Step 2: Service Layer Update

Replace localStorage calls with API calls:

```typescript
// Before (local)
export function getVehicleInsurances(): VehicleInsurance[] {
  return JSON.parse(localStorage.getItem(VEHICLE_INSURANCES_KEY) ?? "[]");
}

// After (API)
export async function getVehicleInsurances(): Promise<VehicleInsurance[]> {
  const res = await fetch("/api/insurances", { headers: AUTH });
  return res.json();
}
```

### Step 3: Database Schema

```javascript
// MongoDB collections
db.createCollection("vehicle_insurances", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      properties: {
        vehicleId: { bsonType: "string" },
        insuranceCompany: { bsonType: "string" },
        annualCost: { bsonType: "decimal128" },
        expirationDate: { bsonType: "date" },
        // ...
      }
    }
  }
});

// Indexes
db.vehicle_insurances.createIndex({ vehicleId: 1, expirationDate: 1 });
db.vehicle_maintenance.createIndex({ vehicleId: 1, serviceDate: -1 });
db.vehicle_taxes.createIndex({ vehicleId: 1, dueDate: 1 });
```

## Examples

### Add Insurance Policy

```typescript
// In Vehiculos.tsx
const handleAddInsurance = (vehicleId: string) => {
  const newIns = createVehicleInsurance(vehicleId);
  setEditInsurance(newIns);
};

// User fills form
const handleSaveInsurance = (insurance: VehicleInsurance) => {
  saveVehicleInsurance(insurance);
  checkVehicleAlerts(); // Regenerate alerts
  setEditInsurance(null);
};
```

### Query Vehicles with Expired Insurance

```typescript
function getVehiclesWithExpiredInsurance(): Vehicle[] {
  return getVehicles().filter((v) => {
    const insurances = getVehicleInsurancesBy(v.id);
    const hasValid = insurances.some((i) => new Date(i.expirationDate) > new Date());
    return !hasValid;
  });
}
```

### Get All Critical Alerts

```typescript
function getCriticalAlerts(): Alert[] {
  checkVehicleAlerts(); // Ensure up-to-date
  return getAlerts().filter((a) => a.severity === "high" && !a.resolved);
}
```
